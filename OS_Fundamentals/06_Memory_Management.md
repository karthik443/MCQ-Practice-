# 06 — Memory Management

## 1. Basics
- A program must be brought into **main memory (RAM)** to run. The CPU can directly access only **registers and main memory**.
- **Memory hierarchy** (fast/small/expensive → slow/large/cheap): Registers → Cache (L1/L2/L3) → RAM → SSD/HDD → Tape.
- **Goals of memory management:** allocation, protection, sharing, relocation, and efficient use.

## 2. Address Binding
| Time | Description |
|------|-------------|
| **Compile time** | The absolute address is known in advance. The code must be recompiled if the location changes (MS-DOS .COM) |
| **Load time** | Relocatable code. The address is fixed when the program is loaded |
| **Execution (run) time** | The address can change during execution. **Needs hardware (MMU)**. Used by modern OSes |

- **Logical (virtual) address:** generated by the CPU.
- **Physical address:** the actual RAM address seen by the memory unit.
- **MMU (Memory Management Unit):** hardware that maps logical → physical addresses at runtime.
- Simple MMU: **physical = logical + relocation (base) register**, with a **limit register** check for protection (`logical < limit`, otherwise a trap).

## 3. Linking & Loading
- **Static linking:** libraries are copied into the executable (bigger file).
- **Dynamic linking:** libraries are linked at runtime (`.dll`, `.so`), using a **stub**. Saves memory, and a shared library is loaded once.
- **Dynamic loading:** a routine is loaded only when it's called.

## 4. Swapping
- Temporarily move a process from memory to the **backing store** (disk) and bring it back later.
- **Roll out, roll in:** used for priority-based scheduling.
- The biggest cost is **transfer time**, which is proportional to the amount of memory swapped.

## 5. Contiguous Memory Allocation
Each process occupies **one contiguous block** of memory.

### Fixed (static) partitioning
- Memory is divided into partitions of fixed size (equal or unequal).
- Suffers from **internal fragmentation**. The degree of multiprogramming is limited to the number of partitions.

### Variable (dynamic) partitioning
- Partitions are created at runtime to exactly fit each process.
- Suffers from **external fragmentation**.

### Allocation strategies ⭐
| Strategy | Rule | Note |
|----------|------|------|
| **First Fit** | First hole big enough | Fast. Generally the best in practice |
| **Next Fit** | Like first fit, but starts searching from the last allocation | |
| **Best Fit** | Smallest hole big enough | Leaves tiny unusable holes. Must search the whole list |
| **Worst Fit** | Largest hole | Leaves big holes. Usually the worst |

**Example:** partitions **100, 500, 200, 300, 600 KB** (in order). Processes **212, 417, 112, 426 KB**.

| Process | First Fit | Best Fit | Worst Fit |
|---------|-----------|----------|-----------|
| 212 | 500 (leaves 288) | 300 (leaves 88) | 600 (leaves 388) |
| 417 | 600 (leaves 183) | 500 (leaves 83) | 500 (leaves 83) |
| 112 | 288 (leaves 176) | 200 (leaves 88) | 388 (leaves 276) |
| 426 | ❌ must wait | 600 (leaves 174) | ❌ must wait |

→ **Best fit** allocates all four here.

## 6. Fragmentation ⭐
| Internal fragmentation | External fragmentation |
|------------------------|------------------------|
| Wasted space **inside** an allocated block (block > request) | Enough total free memory, but **not contiguous** |
| Occurs in fixed partitioning and **paging** (last page) | Occurs in variable partitioning and **segmentation** |
| Fix: smaller or variable-sized blocks | Fix: **compaction**, paging, segmentation with paging |

- **Compaction:** shuffle memory contents to bring all free space together. Needs dynamic relocation and is expensive.
- **50-percent rule:** with first fit, for N allocated blocks about 0.5N blocks are lost to fragmentation (one-third of memory may be unusable).

## 7. Paging ⭐⭐
A **non-contiguous** allocation scheme. It removes external fragmentation.
- Physical memory is divided into fixed-size blocks called **frames**.
- Logical memory is divided into blocks of the same size, called **pages**.
- A **page table** per process maps page number → frame number.
- Page size is a power of 2 (typically **4 KB**).

**Logical address = (page number p, page offset d)**
- If the logical address space = 2ᵐ and the page size = 2ⁿ:
  - offset **d = n bits**
  - page number **p = m − n bits**
  - number of pages = 2^(m−n)
- **Physical address = frame_number × page_size + offset**

### Address translation example
Page size = 1 KB (1024). Logical address = **3085**.
- Page number = 3085 / 1024 = **3**, offset = 3085 mod 1024 = **13**
- If page 3 → frame 5 → physical = 5 × 1024 + 13 = **5133**

### Page table size example ⭐
32-bit logical address, 4 KB page, 4-byte page table entry (PTE):
- Offset = 12 bits, page number = 20 bits → **2²⁰ entries**
- Page table size = 2²⁰ × 4 B = **4 MB per process**. Too big, which is why multilevel paging exists.

### Page Table Entry (PTE) fields
Frame number, **valid/invalid bit**, protection bits (R/W/X), **dirty (modified) bit**, **reference (accessed) bit**, caching disabled.

### Where is the page table?
In main memory, pointed to by the **PTBR (Page Table Base Register)**. Each memory access then takes **2 accesses** (page table + data), so it's slow. The fix is a **TLB**.

## 8. TLB (Translation Lookaside Buffer) ⭐
- A small, fast, **associative** hardware cache of recent page → frame translations.
- **TLB hit:** frame found directly. **TLB miss:** walk the page table and update the TLB.
- **ASID (Address Space ID):** lets the TLB hold entries for multiple processes. Without ASIDs, the TLB is flushed on a context switch.

**Effective Access Time (EAT):**
```
EAT = h × (t + m) + (1 − h) × (t + 2m)
h = TLB hit ratio, t = TLB access time, m = memory access time
```
**Example:** t = 20 ns, m = 100 ns, h = 80%
EAT = 0.8 × 120 + 0.2 × 220 = 96 + 44 = **140 ns**
(If the TLB time is ignored: 0.8 × 100 + 0.2 × 200 = 120 ns.)

## 9. Page Table Structures
1. **Hierarchical / multilevel paging:** page the page table itself (2-level, 3-level, 4-level on x86-64). The outer page table points to inner page tables. Saves memory because unused parts aren't allocated.
   - 32-bit, 4 KB pages, 2-level: `p1 (10 bits) | p2 (10 bits) | d (12 bits)`
2. **Hashed page table:** the virtual page number is hashed, with chaining. Good for address spaces larger than 32 bits.
3. **Inverted page table:** **one entry per physical frame** (not per page), storing <PID, page#>. Saves memory, but searching is slow (a hash is used to speed it up), and shared memory is hard.

## 10. Segmentation
- Memory is divided into **variable-sized logical units** that match the **user's view**: code, data, stack, heap, functions.
- **Logical address = (segment number s, offset d)**
- **Segment table:** each entry has a **base** (start physical address) and **limit** (length).
- If `d < limit` → physical = base + d. Otherwise → **trap (segmentation fault)**.

**Example:** segment 2 has base = 4300, limit = 400.
- (2, 53) → 4300 + 53 = **4353**
- (2, 500) → 500 ≥ 400 → **trap**

### Paging vs Segmentation ⭐
| Paging | Segmentation |
|--------|--------------|
| Fixed-size pages | Variable-size segments |
| Invisible to the user (done by the OS) | Visible to the user (logical view) |
| **Internal** fragmentation | **External** fragmentation |
| Page table: page → frame | Segment table: base + limit |
| Faster, simpler | Easier sharing and protection per segment |

**Segmented paging** (e.g. Intel x86): each segment is paged, which combines the benefits of both.

## MCQ Traps
- Paging → **no external** fragmentation, but **internal** fragmentation is possible.
- Segmentation → **no internal**, but **external** fragmentation is possible.
- Number of frames = physical memory size / frame size.
- Page size = frame size, **always**.
- An inverted page table has entries = **number of physical frames**.
- A larger page size → smaller page table but more internal fragmentation.
